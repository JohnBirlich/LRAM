# RoALT — технический аудит репозитория

Дата: 1 ноября 2026. Ревизия: `901a230` («Release 0.9.0»), ветка `arena/50c7b730-ram`.
Объём: 529 файлов, ~68 600 строк в `.rs/.ts/.tsx/.css/.json`, 285 Rust-тестов.

> Что я реально запускал: `npm ci`, `tsc --noEmit`, `vite build`, `node scripts/check-i18n.mjs` — всё проходит.
> Rust-часть скомпилировать не смог: в песочнице нет тулчейна, а код целиком под Windows
> (`windows` 0.62, `webview2-com`, `Win32_*`, `edition 2024`, `rust-version 1.95`). Выводы по Rust —
> по чтению кода, а не по прогону тестов.

---

## 1. Что это

Локальный менеджер аккаунтов Roblox и мультизапуска клиента для Windows: хранит `.ROBLOSECURITY`
cookies в зашифрованном виде, показывает статус/Robux/друзей, запускает один или много клиентов
в игру, следит за процессами, лимитирует ресурсы, делает превью окон. Всё офлайн, без сервера,
без телеметрии, «только Roblox и GitHub».

Стек: **Tauri 2.12 (Rust) + React 19 + TypeScript + Vite 8 + Tailwind 4 + TanStack Query**,
SQLite через **SQLCipher**, `ts-rs` для генерации IPC-типов, Inno Setup для установщика.

## 3. Как устроена безопасность

**Хранилище.** БД шифруется целиком (SQLCipher, AES-256 на страницу + HMAC-SHA512). Случайный
256-битный ключ лежит рядом в `roalt.db.key`, обёрнутый DPAPI текущего пользователя; без него
файл БД бесполезен на другом ПК/аккаунте. `PRAGMA secure_delete = ON`, WAL, миграции
crash-safe (экспорт → сверка отпечатка всех таблиц → атомарные rename'ы → `resume` после краха).

**Конверт-шифрование секретов.** Один data-key шифрует каждый секрет AES-256-GCM: случайный
nonce на значение, AAD = идентичность строки (`roalt.cookie:<user_id>`) — блоб нельзя переставить
в чужую строку. Data-key хранится обёрнутым:
- DPAPI (по умолчанию) — открывается молча;
- мастер-пароль: `DPAPI(AES-GCM(Argon2id(password)))`, Argon2id 64 MiB / t=3 / p=4;
- код восстановления: то же под Argon2id 256 MiB, код одноразовый, 9 символов из алфавита без
  `0 O 1 I L` (~44 бита), старый код аннулируется при использовании.

Переключение режима только пере-оборачивает ключ; секреты не перешифровываются. `Secret` —
`Zeroizing<String>`, `Debug` печатает `Secret(..)`, data-key обнуляется при lock/auto-lock.

**IPC.** Окна Roblox (`login-*`, `session-*`) вообще не имеют capability, а все команды
дополнительно завёрнуты в `main_only`, который отклоняет вызовы из любого окна кроме `main`.
Capabilities минимальны (окно, диалоги, буфер обмена, opener только на `roblox.com` и
`github.com/inspectsoftware/*`). CSP задан, `frame-ancestors 'none'`, внешний контент в главное
окно не грузится (`on_navigation` → только `tauri.localhost`/`tauri:`).

**Окна Roblox.** Вход — настоящая страница `roblox.com/login` в WebView2 на одноразовом
incognito-профиле под `tmp-webview/<uuid>`, с выключенными autofill/devtools/контекстным меню;
cookie сессии инжектится через `ICoreWebView2CookieManager` (а не `set_cookie`, который теряет
ведущую точку) до первой навигации. После закрытия профиль удаляется, остатки подметаются при
старте. Переменные `WEBVIEW2_*` вычищаются из окружения, чтобы нельзя было подменить профиль.

**Секреты в логах.** Cookie, тикеты, `gameinfo:`, link-коды нигде не логируются: тикеты и URI
живут в `Secret`, диагностика (`diagnostics.rs`) чистит строки по списку `logwatch::SENSITIVE`,
`error.rs` прямо требует «никаких cookie в сообщениях». Это проверяемо и в целом соблюдено.

**Буфер обмена.** Копирование cookie идёт из Rust (`write_secret`, без истории/облака) и
очищается через N секунд или на выходе, причём только если там всё ещё лежит наш секрет.

**Сеть.** Только Roblox, GitHub (проверка обновлений) и опциональный Discord-вебхук; HTTP-клиент
без cookie-jar, `rustls`, редиректы запрещены (кроме апдейтера), у апдейтера белый список хостов
и лимиты размера. Обновление RoALT проверяет **ECDSA P-256** подпись над `"RoALT-Setup-X.Y.Z.exe\n" + байты`,
установщик Roblox — **Authenticode Roblox Corporation**.

## 4. Достоинства

1. **Криптография сделана по-взрослому**, а не «на глазок»: конверт-шифрование, AAD на строку,
   Argon2id с параметрами RFC 9106, DPAPI поверх мастер-пароля (нельзя брутфорсить украденную БД
   вне этой учётки), recovery-код как отдельная обёртка с другим AAD, каппы KDF при импорте
   бэкапа (защита от «злого» файла).
2. **Модель угроз в коде, а не в README.** `main_only`, пустые capability у окон Roblox, CSP,
   одноразовые профили, очистка `WEBVIEW2_*`, `icacls` на data-папку, `secure_delete`, обнуление
   ключей, редактирование логов. Это выше среднего даже для коммерческих тулзов такого класса.
3. **Цепочка поставки закрыта лучше, чем у большинства**: подпись апдейта отдельным ключом +
   проверка подписи установщика Roblox + запрет редиректов на чужие хосты + лимиты размера +
   отказ от установки без клика.
4. **Инженерная дисциплина.** 285 тестов (включая реальные HTTP-тесты клиента против локального
   сервера и фикстуры ответов Roblox в `docs/research/fixtures`), `clippy -D warnings` в CI,
   собственный чекер полноты i18n (сверяет ключи, плейсхолдеры, категории плюрализации),
   `ts-rs` вместо ручных типов IPC, все URL в одном файле, комментарии объясняют *почему*
   (включая `ponytail:` — явно помеченные компромиссы).
5. **Честность про Roblox.** Документация фиксирует, где реальность разошлась с ожиданиями
   (CSRF из 403, ротация cookie, `x-ratelimit-reset` вместо `Retry-After`, исчезнувшее
   «last online», HBA/челленджи, allowlist FFlags), и код это отражает.
6. **Клиент не модифицируется**: мультиинстанс через named mutex/event до старта, лимиты через
   job objects/priority/affinity, превью через Windows.Graphics.Capture. Для анти-чита это
   принципиально более безопасный подход, чем патчи бинаря.
7. **Продуктовая зрелость**: 17 языков + английский, тёмная/светлая тема, свой акцент, фон,
   плотность, drag&drop, tray, глобальный hotkey «убить всё», диагностика, история крашей,
   экран Unlock, сплэш, обработка ошибок через единый `AppError`.
8. **Фронтенд собран аккуратно**: строгий TS без `any`, ни одного `dangerouslySetInnerHTML`,
   один `QueryClient` с инвалидацией по событиям бэкенда, 207 `aria-*` атрибутов, обработка
   потери фокуса, ErrorBoundary.

## 5. Недостатки и риски

### P1 — то, что реально влияет на безопасность

1. **Режим по умолчанию (DPAPI) не защищает от вредоноса.** Ключ БД и обёртка data-key читаются
   молча любым процессом под тем же пользователем. Windows Hello / мастер-пароль стоят только на
   *показ* и *копирование* cookie — но запуск клиента и работа с API идут без них. То есть
   мастер-пароль защищает от «кто-то сел за мой ПК», а не от стилера. Это стоит писать прямо в
   README и в настройках, а не только «Encrypted on this PC».
2. **`take_over()` — самое рискованное место в проекте.** Чтобы перехватить `ROBLOX_singletonEvent`
   у уже запущенного клиента, код делает `OpenProcess(PROCESS_DUP_HANDLE)` в процесс Roblox и
   `DuplicateHandle(..., DUPLICATE_CLOSE_SOURCE)`. Hyperion/Byfron на актуальных клиентах такие
   операции, как правило, блокирует, а со стороны анти-чита это выглядит как внешнее вмешательство
   в процесс. Функция не включена по умолчанию (только по подтверждению), но её надо либо
   убрать, либо снабдить явным предупреждением о риске бана/неработоспособности.
3. **`protect_shared_login` (включён по умолчанию) держит `RobloxCookies.dat` и `appStorage.json`
   с share mode 0.** Это блокирует сам Roblox и любые сторонние тулзы; при неудачном тайминге
   может оставить клиент без сохранения сессии. Обоснование в коде есть (ошибка 773), но дефолт
   агрессивный.
4. **Cookie — это полный доступ к аккаунту в обход 2FA.** Пользователь хранит 10+ аккаунтов в
   одном месте: одна утечка `.roalt`-бэкапа со слабым паролем = потеря всех аккаунтов. Приложение
   честно предупреждает, но модель «много cookie в одном файле» — токсичная по своей природе.
5. **Установщик не подписан Authenticode** (в release.yml стоит `HAS_SIGNPATH`, SignPath ещё не
   одобрен). Для приложения, которое просит cookie Roblox, отсутствие подписи издателя —
   серьёзный минус доверия: SmartScreen ругается, пользователь не может проверить, что бинарь
   собран из этого кода.
6. **Нет файла LICENSE.** Юридически это «все права защищены»: форк, редизайн и распространение
   без разрешения автора неправомерны. Для вашей задачи («переделать под кастомный дизайн») это
   блокер, который нужно решить до работы.

### P2 — архитектурные и эксплуатационные

7. **Жёсткая привязка к внутренностям Roblox.** Имя singleton-события, имена файлов LocalStorage,
   форматы клиентских логов, allowlist FFlags, набор эндпоинтов — всё это может измениться без
   предупреждения (мультиинстанс уже ломался в середине 2025). Приложение к этому готово
   архитектурно (фича отваливается с сообщением), но обещать стабильность нельзя.
8. **Форк будет обновлять себя с upstream.** `self_update.rs` жёстко ходит в
   `api.github.com/repos/inspectsoftware/RoALT/releases/latest` и проверяет подпись публичным
   ключом автора. Если вы сделаете свой дизайн и не поменяете эти константы, приложение тихо
   предложит (и по клику поставит) **оригинальный** RoALT поверх вашей сборки — весь редизайн
   исчезнет. Тот же ключ означает, что вы физически не сможете выпускать свои обновления, пока
   не сгенерируете свою пару ключей и не перепишете `PUBLIC_KEY`.
9. **Тестов нет там, где их не хватает больше всего**: 0 тестов на фронтенде, нет e2e на
   Tauri-команды. В `docs/MILESTONES.md` UI проверялся руками («Hand-tested by the user»).
   Для проекта, который трогает чужие аккаунты, это узкое место.
10. **Форматирование не зафиксировано.** Нет `rustfmt.toml`, при этом 1464 строки длиннее 100
    символов (стиль явно «120 колонок»), в `model.rs` (строка ~489) сбит отступ; CI не запускает
    `cargo fmt --check`. Диффы будут шумными, контрибьюторам больно.
11. **Раздутые модули**: `commands.rs` — 2558 строк, `instances/tracker.rs` — 2415,
    `instances/window.rs` — 1185, `launcher/bulk.rs` — 1201. `commands.rs` уже просится на
    разбиение по фичам.
12. **Блокирующие вызовы.** Запросы к SQLite идут синхронно в tokio-потоке (в коде помечено
    `ponytail`), чтение/запись файлов обёрнуты в `blocking` лишь местами. На большом списке
    аккаунтов или медленном диске это может подвешивать IPC.
13. **Фронтенд-бандл 2.0 МБ (557 КБ gzip) одним чанком**, без code splitting — при том, что
    половина приложения (серверы, performance, debug, discord) нужна редко.
14. **Документация разошлась с кодом.** `docs/DESIGN.md` всё ещё «proposal, 2026-10-24, nothing
    is built yet» и описывает структуру `QuikSwitch/`, файлы `lib.rs`, `instances/singleton.rs`,
    `platform.rs`, `auth.rs`, `roblox_api/users.rs` — которых нет. README описывает 0.9.0 и
    ссылается на `inspectsoftware/RoALT`, а репозиторий — `JohnBirlich/RAM`.
15. **Хрупкость тулчейна.** `edition 2024`, `rust-version = "1.95"`, Tauri 2.12, reqwest 0.13,
    rusqlite 0.40, TS 7, Vite 8 — сборка требует свежайших компиляторов; на CI `stable` со
    временем «уедет» и сборка может перестать воспроизводиться.
16. **`panic = "abort"` в релизе** + 790 `.unwrap()`/`.expect()` в коде (значительная часть —
    в тестах, но не все). Panic hook пишет в лог, но приложение просто исчезает.
17. **Привязка к GPU/композитору.** Превью идут через Windows.Graphics.Capture + D3D11; на
    виртуалках, RDP, мульти-GPU и просто старых драйверах возможны деградации; много клиентов ×
    превью = заметная нагрузка (есть настройки FPS превью и «спящие» окна, но дефолт — 15 FPS на
    карточку).
18. **Мелочи-поверхности**: `debug_log` позволяет UI писать произвольные строки в лог (log
    injection); `background_set` и `accounts_import_ram` принимают произвольный путь из UI
    (при компрометации вебвью — чтение файлов, ограниченное валидацией картинки/лимитом 32 МБ);
    нет ограничения попыток на `vault_unlock` (тормозит только Argon2).

### P3 — вкусовое / продукт

19. Дефолты приватности спорные: `discord_presence: true` (публикует «Playing RoALT» и число
    альтов в Discord) и `self_update: true` (пинг GitHub при старте). Для «local-only» позиции
    логичнее оба выключить.
20. `allow_public_networks` по умолчанию `true` (миграция включает его всем), то есть
    «public network guard» фактически опция. Ранее было наоборот.
21. `lighter_rendering` и `low_graphics` включены по умолчанию — приложение по умолчанию правит
    `ClientAppSettings.json` внутри установки Roblox и настройки графики аккаунтов. Функционально
    оправдано, но «из коробки меняет чужой софт» — не всем понравится.
22. Локализация неполная: чекер выдаёт предупреждения о строках, оставшихся на английском
    (pt, vi, sv, zh и др.), и часть бренда зашита в код.

## 6. Подводные камни при эксплуатации

- **Не запускайте на другой учётке Windows или после переноса папки с другого ПК** — DPAPI не
  расшифрует; приложение скажет об этом и предложит переименовать `roalt.db` и импортировать
  `.roalt`-бэкап. Это не баг, это следствие дизайна.
- **Сетевые папки и OneDrive** для data-папки — плохая идея (DPAPI + WAL + блокировки файлов).
- **Отключённый диск** с перенесённой data-папкой = отказ запуска с понятным сообщением
  (`location.json`), а не «пустой новый vault» — хорошо, но знать надо.
- **Microsoft Store-версия Roblox не поддерживается** (её нельзя запустить по `roblox-player:`).
- **Bloxstrap/Fishstrap**: поддержаны частично — FFlags не применяются (бутстраппер копирует свой
  файл), установщик Roblox не запускается поверх.
- **При аварийном завершении RoALT** (kill) остаются: job-объекты с CPU-лимитами, изменённый
  `ClientAppSettings.json`, «призрачные» скрытые окна, взятые лимиты. Часть восстанавливается при
  следующем старте (`restore`, `sweep`, `recover`), job-лимиты снимаются только при нормальном
  выходе.
- **Античит игр** может реагировать на синтетический ввод anti-AFK; Roblox официально не
  поддерживает несколько клиентов одновременно.
- **Тикет запуска виден в командной строке процесса Roblox** любому процессу на машине (так
  устроен сам Roblox). Приложение свои логи чистит, но ОС — нет.

## 7. Безопасно ли использовать

**Короткий ответ: да, но с оговорками, и «безопасно» ≠ «без последствий».**

Что защищено хорошо: данные на диске (SQLCipher + конверт-шифрование), сеть (TLS, минимум хостов,
подписанные обновления), IPC (жёсткая изоляция окон Roblox), логи и буфер обмена.

Что остаётся риском и от кода не зависит:

1. **Юридический/ToS-риск.** Хранение cookie нескольких аккаунтов, мультиинстанс, авто-вход и
   anti-AFK — против духа правил Roblox; баны аккаунтов возможны и случаются у подобных
   инструментов. Никакая криптография это не отменяет.
2. **Модель «cookie = аккаунт».** Один украденный cookie = аккаунт целиком, 2FA не спасает.
   Дефолтный DPAPI-режим не защищает от вредоноса под вашей учёткой.
3. **Доверие к бинарю.** Ставьте только из официальных релизов (или собирайте сами); установщик
   пока без подписи издателя.
4. **Приватность.** По умолчанию включены rich presence в Discord и проверка обновлений на GitHub.

Рекомендации пользователю: включить мастер-пароль + recovery-код (хранить офлайн), выключить
`discord_presence`, выставить `self_update` по желанию, не хранить `.roalt`-бэкапы в облаке без
сильного пароля, не запускать на чужой/рабочей машине, не использовать «основной» аккаунт как
первый в списке.

Рекомендации автору кода: подписать установщик, добавить `LICENSE`, выключить спорные дефолты,

хотя бы smoke-тесты фронтенда.

## 8. Дизайн: что можно переделать

Хорошая новость: визуальный слой изолирован намного лучше среднего.

- **Токены**: `src/theme.css` (1504 строки) — `@theme inline` маппит CSS-переменные в
  Tailwind-утилиты (`bg-panel`, `text-dim`, `border-line`, `text-accent`, …). В `:root` и
  `:root[data-theme="light"]` лежат `--bg/--panel/--raised/--hover/--sel/--line/--text/--dim/--accent`,
  а также «глубина»: `--face`, `--raise`, `--press`, `--well`, `--primary`, `--shadow`.
  Тема «Soft Deck» — неоморфная: тени в две стороны, острые углы, лаймовый акцент.
- **Акцент пользователя** генерируется из одного цвета через `oklch()`/`color-mix()` с
  автоматической коррекцией контраста для светлой/тёмной темы — это уже готовый механизм
  кастомизации (Settings → акцент, 9 пресетов + пипетка).
- **Плотность** (`Detailed`/`Compact`) и **раскладка табов** (верх/сбоку) — тоже настройки.
- **Компоненты**: `src/ui/*` (Dialog, Toast, controls, Resizable, TitleBar, Icon) — небольшие,
  стилизованы классами из `theme.css`, а не инлайн-стилями.
- **Что не токенизировано**: радиусы (`border-radius` зашиты в правила `theme.css` — 16/18/20 px
  у панелей, 10 px у контролов, 99 px у пилюль), типографика (Geist/Geist Mono, размеры в
  утилитах), ~40 hex-литералов в `.tsx` (свотчи групп, арт сплэша, логотип), иконки — инлайн-SVG
  в `ui/Icon.tsx`.

**Вывод:** сменить визуальный язык (цвета, тени, радиусы, типографику, «плоско/стекло/терминал»)
можно правкой `theme.css` + `ui/*` — это 1–3 файла на 80 % эффекта. Переработка *раскладки*
(навигация, Home, Accounts) — уже `App.tsx`, `features/dashboard/*`, `features/accounts/*`.

**Чего нельзя забыть при ребрендинге** (иначе форк либо не соберётся «как свой», либо
самообновится в оригинал):

| Место | Что там |
|---|---|
| `package.json`, `src-tauri/Cargo.toml`, `tauri.conf.json` | имя продукта, `identifier: com.inspectsoftware.roalt`, версия |
| `self_update.rs` | `LATEST` (репозиторий), `PUBLIC_KEY` (ключ подписи — нужна своя пара) |
| `rpc.rs` | `CLIENT_ID` Discord, ссылки Download/Invite |

| `installer/RoALT.iss`, `.github/workflows/*` | publisher, AppId, winget id, пути |
| `src/i18n/locales/*.json` (18 файлов) | 65 вхождений «RoALT» в английском, ~по столько же в переводах |
