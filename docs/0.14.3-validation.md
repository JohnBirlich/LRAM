# 0.14.3: immediate limits and official-client handoff

Supersedes 0.14.2's universal warm-up at the user's explicit request. CPU/Eco apply immediately in all launch/loading/teleport states. Legacy warmupS remains serialized but is inactive. Hung-client and Full quality exceptions are safety/user overrides, not timers. FPS/graphics remain launch-time and explicit-restart settings.

User evidence: official Roblox launch PID disappears in 5–6 seconds, its matched log keeps growing and reports game entry, while window/metrics/close remain tied to the original PID. Some clients retain their PID and receive window setup normally. This establishes a stale-identity symptom, not proof of why the OS ownership API did not recover it.

Added exact +browsertrackerid:<random launch token>+ command-line matching as fallback to Restart Manager log ownership. A query-only OS call reads the command line into zeroizing local storage; raw arguments/tickets are never logged. Only Roblox executable candidates from the existing enumeration qualify, with start-time, uniqueness, account-mismatch and taken-PID checks. No nearest-process/window guesses. If the token is not retained or the OS query is denied, recovery remains unconfirmed rather than targeting another account.

Regression coverage: official handoff without Restart Manager ownership restores new PID, routes limits/metrics/close and re-runs window setup; exact token boundaries reject prefixes/unrelated launches; all profiles have zero warm-up before/after teleport. Frontend build and capacity/privacy tests pass locally. Native Windows tests/Clippy must pass CI before publication.

Separate observed failures: WebLogin HTTP 429 followed by authentication failure (rate limiting, not a generic crash); HTTP 403 on accounts 12–14; Roblox blocks RivaTuner RTSSHooks64.dll. These are not proof that RTSS caused every handoff, and SignalR websocket closure alone is not game-server disconnect proof. Existing-job warnings after LRAM restart mean CPU Off cannot certify that an old/foreign job cap was removed.

Real-PC acceptance: after launch handoff each card obtains the actual client window and metrics, tiny/minimize applies, Show/Close/Force close affect only its own client, no duplicate same-account game clients; repeat with delayed window creation and multiple concurrent accounts. Immediate low CPU caps can make loading slower/less stable. No actual user-PC reproduction is claimed by CI.
