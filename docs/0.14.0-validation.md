- `npm run build`: TypeScript, translation-key validation, production build. Existing large-chunk warning remains.
- `npm run test:capacity`: 8 empirical capacity tests.
- `npm run test:privacy`: non-mutating account/group display projections and preserved business IDs.

Added coverage: account-scoped profile storage, privacy settings round-trip, strict CPU policy through focus/loading/teleport/full-quality exemptions, unchanged live FPS while restart is pending, manual strict cap ceiling, adapter identity deduplication. Existing process-identity/recovery tests remain enabled.

Browser tests (development IPC mocks, not Windows process tests):

- Privacy toggle: Accounts/Home/Monitor body text, title/aria/input attributes do not contain mock usernames; account avatars are absent and Home preview canvases are not visible. Hardware display is hidden. Turning privacy off restores original identities without saving masked aliases/notes.

## Required real Windows / user-PC checks

Browser mocks and CI cannot certify the user's hardware or a particular Roblox experience. Before relying on resource targets, check:

1. Restart LRAM after enabling Privacy. Confirm it is still enabled. Review Home account tabs/target inputs, Accounts, Monitor, tooltips, dialogs, game/favourite labels, thumbnails, IP/country and settings path hints. Exported files and disk logs are **not** automatically anonymized; review separately before sharing.
2. On the reported one-GPU/three-monitor PC: verify adapters and Displays separately. Count real connected screens; check Windows-reported name/current resolution/Hz or unknown. Compare GPU identities with Windows, including virtual/remote devices. Two genuine identical-model GPUs must not be collapsed. The user's original repeated-4070-SUPER scenario has not been reproduced in CI.
3. Launch clients with no old per-account overrides, apply global ULTRA and then individual ULTRA; confirm requested/applied 1% or 2% through initial loading, foreground switching and teleport/rejoin. There must be no warmup/grace release. Use a time series, not a promise about every instantaneous Task Manager value. Check errors on foreign jobs/insufficient access.
4. Measure window rectangles before/after applying ULTRA and after launching; no forced 160×120 or resolution change. Explicit Tile windows is a separate user action.
5. Selected Apply must leave other clients and stored-only accounts untouched. For all-running, start another client after the request snapshot; it must not join that operation. Account overrides intentionally persist to future launches of affected accounts.
6. Change FPS/graphics. CPU/Eco should update without restart; live FPS must not be relabeled as applied. Confirm Requires restart, cancel the restart, then confirm it. Only the selected client may close/relaunch. Progress/same-server restoration is not guaranteed; Roblox/bootstrapper flag support must be checked in practice.
7. During confirmed restart: try Stop all, a blocked close, process PID reuse and another simultaneous launch. Never launch a duplicate or terminate an unrelated PID. Existing identity-safe recovery scenario from 0.13.0 must still hold, including the user's ten-client case.
8. Extremely low CPU ceilings can cause slow loads/disconnects. Compare stability and measured private commit/working set; no fixed RAM or account-count guarantee.

## Release gates

Do not publish an installer until the exact release commit passes Windows checks and the release build. Preserve all previous release assets. Verify installer plus SHA256SUMS, target commit/tag and final public Latest status. Code-signing/Defender clearance is not part of this release and is not claimed.
